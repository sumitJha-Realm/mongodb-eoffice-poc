Audit & Security i

  
Home / Audit — immutable trails with old/new values (RFP Appx B Section 2)

  

    
What auditing does here, and what it can be configured to do

    

      

        Three complementary layers (all active in this PoC)
        
    
          
  • Native MongoDB Enterprise audit log — server-side, tamper-resistant, written by mongod itself. Records authentication (success and failure), user/role changes, DDL (create/drop collection or index), shutdown, and CRUD on chosen collections. Applications cannot bypass it.
    • 
          
  • Application audit trail — append-only audit_log collection with old and new values captured by change streams (pre/post images). RBAC allows insert+read only.
    • 
          
  • Ops Manager — project-level audit of who changed deployment, users, backup and alert settings.
    • 
        

      

      

        What it can be configured to do
        
    
          
  • Destination: JSON/BSON file, syslog or console; ship to SIEM (Splunk/ELK) via filebeat.
    • 
          
  • Filter by event type, user, role, database/collection with a match expression (this PoC audits poc.audit_log and poc.personnel_confidential writes).
    • 
          
  • auditAuthorizationSuccess: also log successful reads/writes, not just failures (heavier; scope it with a filter).
    • 
          
  • Redact query values via log redaction for classified fields.
    • 
          
  • Pair with Queryable Encryption so even an authorised DBA's audit trail never exposes plaintext.
    • 
          
  • Retention: file rotation + immutable object storage (S3 Object Lock / WORM) for long-term evidence.
    •

Key hierarchy

Who sees what

        
Authorised appdriver encrypts queries + decrypts results client-side
